# Oreum

Дешборд для відстеження акцій. Пет-проєкт, один розробник.
Роадмап і скоуп — у `PLAN.md`. Читай його перед тим, як пропонувати нову фічу.

## Мета проєкту

Відточити AI-assisted development end-to-end. Тому:
пояснюй нетривіальні рішення коротко, а не просто видавай код.
Якщо є два розумні підходи — назви обидва одним реченням і порекомендуй один.

## Стек

Next.js 16 (App Router) + React 19, TypeScript, pnpm.
Supabase (Postgres, auth), Vercel, Lightweight Charts.

## Команди

- `pnpm dev` — dev-сервер
- `pnpm build` — продакшн-збірка
- `pnpm lint` — eslint (flat config, `eslint.config.mjs`)
- `pnpm exec tsc --noEmit` — тайпчек (окремого npm-скрипта немає)

Завжди `pnpm`, ніколи `npm` чи `yarn`.

## Правила

- Скоуп священний. Не додавай фіч, яких немає в поточному мілстоуні `PLAN.md`.
  Ідея за межами мілстоуна — в розділ «Пізніше», не в код.
- Ключі API тільки на сервері: route handlers або server actions.
  Ніколи не `NEXT_PUBLIC_` для того, що коштує грошей.
- Кожен виклик зовнішнього API даних проходить через кеш у Supabase.
  Безкоштовні тарифи провайдерів жорсткі — прямий запит на кожен рендер вб'є ліміт.
- RLS вмикається одразу при створенні таблиці, не «потім».
- Англійською в чаті та в коді, комітах і коментарях.
  `PLAN.md` та інші планувальні документи — українською.

## Граблі

- Server Components за замовчуванням. `"use client"` — тільки там, де є стан
  або браузерні API. Lightweight Charts — клієнтський.
- Ціни акцій — це гроші: `numeric`, ніколи `float`.
- Ринкові дані завжди в UTC у базу, конвертація в таймзону лише на відображення.
- Дані з провайдерів приходять брудні: пропуски днів, спліти, після-маркет.
  Не припускай, що ряд суцільний.

## Робочий процес

- Спершу план, потім код. На нетривіальних задачах — plan mode.
- Дрібні коміти, англійською, imperative mood.
- Гілка на кожну зміну, PR у `master`. Ніколи не коміть прямо в `master`.
- Прийняте архітектурне рішення — рядок у «Журнал рішень» у `PLAN.md`.
  Рішення не живуть у чаті.
